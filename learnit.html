Linux room

Linux căn bản để vận hành server thật

Mục tiêu của phòng này là dùng Linux như người vận hành hệ thống: biết máy đang chạy gì, lỗi nằm ở đâu, quyền file có đúng không, port nào đang mở, ổ nào sắp đầy và service nào cần xử lý.

Master course

Giáo trình master: Linux căn bản

Học theo 4 lớp: hiểu nguyên lý, làm lab, tự trả lời câu hỏi, rồi xử lý tình huống thực tế.

01

Lý thuyết cốt lõi

Process, filesystem, permission, network, storage và service là nền để vận hành mọi server.

02

Lab master

Tạo user deploy, cấu hình SSH key, dựng nginx, cố tình sai quyền rồi tự sửa bằng namei/chown/journalctl.

03

Câu hỏi phải trả lời được

Vì sao file đúng chmod nhưng nginx vẫn 403? Khác nhau giữa reload và restart? Khi nào dùng lsof +L1?

04

Tình huống thực tế

Disk full lúc nửa đêm, SSH vẫn vào được nhưng app 500; phải tìm file lớn, log, inode và process giữ file đã xóa.

1. Shell và file system

Học cách di chuyển, đọc file log, tìm file, nén/giải nén, đồng bộ dữ liệu và thao tác an toàn với thư mục hệ thống.

2. User, group, permission

Đây là phần rất quan trọng khi web lỗi vì nginx/app không đọc được file, không ghi được cache hoặc upload thất bại.

3. Process và systemd

Biết đọc trạng thái service, restart đúng dịch vụ, xem log theo unit và xác định service chết vì config hay tài nguyên.

4. Network và storage

Hai nhóm lỗi phổ biến nhất khi vận hành: không vào được web vì port/DNS/firewall, hoặc hệ thống lỗi vì disk full/inode full/mount sai.

01Web Website không vào được Browser báo không kết nối, timeout hoặc refused. 
curl -I https://domain.com
ping -c 3 domain.com
dig domain.com +short
nc -vz domain.com 443
 Tách lỗi DNS, network, port, web server. Nếu nc fail thì kiểm tra firewall/nginx.

sudo nginx -t
sudo tail -120 /var/log/nginx/error.log
pm2 status
pm2 logs --lines 150
sudo ss -tulpen
 Tìm upstream trong nginx, kiểm tra app/backend, restart đúng service sau khi đọc log.
03Web HTTP 503 Service Unavailable Service bảo trì, upstream unavailable hoặc app quá tải. 
curl -I https://domain.com
sudo systemctl status nginx --no-pager
pm2 status
docker compose ps
 Kiểm tra maintenance mode, service health, queue/worker, rate limit.
04Web HTTP 404 sai trang Sai root/location, rewrite, file không tồn tại hoặc route frontend chưa fallback. 
sudo nginx -T | grep -n "root\|location\|try_files"
ls -lah /var/www/app
curl -I https://domain.com/path
 Kiểm tra đúng webroot và try_files cho SPA nếu cần.
05Web HTTP 403 Forbidden Sai permission, thiếu index, deny rule hoặc SELinux/AppArmor. 
namei -l /var/www/app/index.html
ls -lah /var/www/app
sudo tail -80 /var/log/nginx/error.log
getenforce 2>/dev/null || true
 Sửa owner/permission thư mục cha, kiểm tra index và rule deny.
06Web Redirect loop HTTP->HTTPS/proxy header sai, app tin sai scheme hoặc Cloudflare mode sai. 
curl -IL https://domain.com
sudo nginx -T | grep -n "return 301\|proxy_set_header"
 Đặt X-Forwarded-Proto đúng, tránh redirect kép ở app và nginx.
07Nginx Nginx reload lỗi Config sai syntax, include file lỗi hoặc port conflict. 
sudo nginx -t
sudo systemctl status nginx --no-pager
sudo journalctl -u nginx -n 100 --no-pager
 Không reload khi nginx -t fail. Mở file/line báo lỗi rồi sửa.
08Nginx Port 80/443 bị chiếm Nginx không start vì service khác giữ port. 
sudo ss -tulpen | grep -E ":80|:443"
sudo lsof -i :80 -P -n
sudo lsof -i :443 -P -n
 Dừng service chiếm port hoặc đổi listen.
09DNS Domain trỏ sai IP Domain vào server cũ hoặc không resolve. 
dig A domain.com +short
dig AAAA domain.com +short
curl -s https://ifconfig.me && echo
 So sánh IP DNS với IP server. Chú ý AAAA IPv6 có thể trỏ sai.
10DNS DNS propagation/chậm cập nhật Máy này thấy IP mới, máy khác vẫn IP cũ. 
dig @1.1.1.1 domain.com +short
dig @8.8.8.8 domain.com +short
dig domain.com TTL
 Chờ TTL hoặc giảm TTL trước khi đổi DNS.
11SSL SSL hết hạn Browser báo cert expired hoặc curl fail certificate. 
echo | openssl s_client -connect domain.com:443 -servername domain.com 2>/dev/null | openssl x509 -noout -dates -issuer
sudo certbot certificates
 Renew cert, kiểm tra certbot timer và reload nginx.
12SSL Sai certificate/domain Cert không khớp domain hoặc default cert. 
curl -vk https://domain.com 2>&1 | grep -Ei "subject|issuer|SSL"
sudo nginx -T | grep -n "server_name\|ssl_certificate"
 Kiểm tra server_name và đường dẫn cert đúng vhost.
13Upload Upload thất bại file lớn Failed to fetch, 413, timeout, hoặc API ngắt giữa chừng. 
grep -R "client_max_body_size\|proxy_request_buffering\|proxy_read_timeout" /etc/nginx 2>/dev/null
sudo df -h
pm2 logs sentinel-api --lines 150
 Tăng limit/timeout, tắt buffering nếu stream, kiểm tra dung lượng/quyền thư mục.
14Upload Upload báo permission denied API không ghi được thư mục storage/upload. 
sudo ls -ld /path/to/upload
namei -l /path/to/upload
pm2 logs --lines 120
 Chown/chmod đúng user chạy app. Kiểm tra thư mục cha.
15Storage Disk full Không ghi file, database lỗi, nginx/app 500. 
df -h
sudo du -xh / | sort -h | tail -50
sudo lsof +L1
 Tìm thư mục lớn, log, backup cũ, file đã xóa nhưng process giữ.
16Storage Inode full Còn dung lượng GB nhưng không tạo được file. 
df -ih
sudo find /var -xdev -type f | sed "s#/[^/]*$##" | sort | uniq -c | sort -n | tail -30
 Xóa/rotate nhiều file nhỏ, cache/session/log nhỏ.
17Storage Mount ổ ngoài mất Dung lượng còn lại sai, thư mục storage rỗng hoặc về ổ root. 
lsblk -f
findmnt
cat /etc/fstab
sudo mount -a
 Kiểm tra UUID fstab, quyền mount, tránh ghi nhầm vào thư mục mountpoint trên root.
18Performance CPU cao Load cao, request chậm, fan/CPU 100%. 
uptime
ps aux --sort=-%cpu | head -20
top -o %CPU
 Xác định process, endpoint/log liên quan. Không kill vội DB/app chính.

sudo iotop 2>/dev/null || true
 Tìm process ghi/đọc nhiều, backup/log/database gây IO wait.

nc -vz SERVER 22
ssh -vvv user@SERVER
sudo systemctl status ssh --no-pager
sudo tail -120 /var/log/auth.log
 Tách lỗi port/firewall/sshd/auth/key/fail2ban.

ping -c 3 8.8.8.8

 Nếu ping IP ok nhưng dig fail là DNS. Nếu cả ping fail kiểm tra route/gateway.

Docker/Compose command matrix

Bảng master Docker/Compose đầy đủ để học và vận hành

Nhấp đúp vào ô lệnh màu đen để copy. Học theo nhóm từ trên xuống để hiểu cách Docker hoạt động trước khi dùng vào production.

01Docker CLI Phiên bản/thông tin hệ Hiểu Docker client/server, storage driver, cgroup, root dir. 
docker version
docker info
 Dùng đầu tiên khi nhận máy có Docker.
02Image Liệt kê image Xem image local, size, tag. 
docker image ls
docker images
 Image dangling có thể dọn nếu không dùng.
03Image Pull image Tải image từ registry. 
docker pull nginx:1.27
docker pull postgres:16
 Pin tag cụ thể, tránh latest production.
04Image Inspect image Xem metadata, env, entrypoint, layer. 
docker image inspect IMAGE:TAG
docker history IMAGE:TAG
 Cẩn thận secret bị bake vào layer.
05Image Tag image Đổi/gắn tag trước khi push. 
docker tag app:local registry.example.com/app:v1.0.0
 Tag là nhãn, không copy image mới.
06Image Remove image Xóa image local. 
docker rmi IMAGE:TAG
docker image prune
 Không xóa image đang được container dùng.
07Build Build image Build Dockerfile thành image. 
docker build -t app:dev .
docker build --no-cache -t app:debug .
 --no-cache dùng khi nghi cache sai.
08Build Build với file khác Dùng Dockerfile riêng cho prod/dev. 
docker build -f Dockerfile.prod -t app:prod .
 Context . càng nhỏ càng tốt, dùng .dockerignore.
09Build Build args Truyền tham số build không nhạy cảm. 
docker build --build-arg NODE_ENV=production -t app:prod .
 Không truyền secret bằng build-arg.
10Container Chạy container đơn giản Tạo và chạy container từ image. 
docker run --name web -p 8080:80 nginx:1.27
 Nếu không -d sẽ chạy foreground.
11Container Chạy nền Run detached mode. 
docker run -d --name web -p 8080:80 nginx:1.27
 Đọc logs sau khi chạy.
12Container Liệt kê container Xem container đang chạy/tất cả. 
docker ps
docker ps -a
 Exited container giữ log/layer.
13Container Start/stop/restart Điều khiển vòng đời. 
docker start web
docker stop web
docker restart web
 Stop gửi SIGTERM rồi SIGKILL sau timeout.
14Container Remove container Xóa container. 
docker rm web
docker rm -f web
 -f kill container, dùng cẩn thận.
15Container Rename container Đổi tên container. 
docker rename old_name new_name
 Tên container cần duy nhất.
16Container Run có env Truyền biến môi trường. 
docker run -e NODE_ENV=production -e PORT=3000 app:prod
 Không truyền secret nhạy cảm qua shell history nếu có cách khác.
17Container Run có env-file Dùng file env. 
docker run --env-file .env app:prod
 Đặt quyền .env chặt.
18Container Restart policy Tự khởi động lại container. 
docker run -d --restart unless-stopped --name app app:prod
 Không thay thế healthcheck đúng.
19Logs Đọc log Xem log container. 
docker logs --tail 200 app
docker logs -f --tail 100 app
 Ứng dụng nên log ra stdout/stderr.
20Logs Log kèm thời gian Debug timeline. 
docker logs -t --since 1h app
docker logs --until 10m app
 Hữu ích khi RCA.
21Exec Vào container Mở shell trong container. 
docker exec -it app sh
docker exec -it app bash
 Không sửa thủ công lâu dài trong container.
22Exec Chạy lệnh trong container Kiểm tra env/file/process. 
docker exec app printenv
docker exec app ps aux
docker exec app ls -lah /app
 Dùng để debug runtime.
23Copy Copy file ra/vào Lấy log/config hoặc đẩy file test. 
docker cp app:/app/log.txt ./log.txt
docker cp ./file.txt app:/tmp/file.txt
 Không dùng thay quy trình deploy.
24Inspect State container Xem exit code, health, started/finished. 
docker inspect app --format "{{json .State}}"
 State giúp biết vì sao restart.
25Inspect Mount/network Xem mount và IP. 
docker inspect app --format "{{json .Mounts}}"
docker inspect app --format "{{json .NetworkSettings.Networks}}"
 Ẩn output nếu có secret.
26Stats Tài nguyên realtime CPU/RAM/network per container. 
docker stats
docker stats app
 Dùng khi app chậm.
27Top Process trong container Xem process không cần exec. 
docker top app
 Hữu ích container không có ps.
28Port Port mapping Xem port publish. 
docker port app
docker ps --format "table {{.Names}}\t{{.Ports}}"
 Port nội bộ khác port host.
29Network Liệt kê network Xem network Docker. 
docker network ls
docker network inspect bridge
 Compose tạo network riêng.
30Network Tạo network Tạo bridge network user-defined. 
docker network create app_net
docker run --network app_net --name app app:prod
 User-defined network có DNS theo tên container.
31Network Kết nối/ngắt network Gắn container vào network. 
docker network connect app_net app
docker network disconnect app_net app
 Cẩn thận làm mất kết nối service.
32Volume Liệt kê volume Xem volume local. 
docker volume ls
docker volume inspect VOLUME
 Volume thường nằm dưới /var/lib/docker.
33Volume Tạo volume Tạo volume trước. 
docker volume create app_data
 Dễ quản lý hơn để Docker tự tạo.
34Volume Run với volume Mount data bền vững. 
docker run -v app_data:/var/lib/postgresql/data postgres:16
 Dữ liệu DB phải ở volume/bind mount.
35Volume Bind mount Mount thư mục host. 
docker run -v /srv/app/data:/data app:prod
 Quyền host path rất quan trọng.
36Volume Backup volume Đóng gói volume ra tar.gz. 
docker run --rm -v app_data:/data -v $PWD:/backup alpine tar czf /backup/app_data.tgz -C /data .
 Stop app/DB hoặc dùng backup native để nhất quán.
37Volume Restore volume Khôi phục volume. 
docker run --rm -v app_data:/data -v $PWD:/backup alpine sh -c "cd /data && tar xzf /backup/app_data.tgz"
 Restore vào môi trường test trước.
38Registry Login registry Đăng nhập registry. 
docker login registry.example.com
 Không để password trong command history.
39Registry Push image Đẩy image. 
docker push registry.example.com/app:v1.0.0
 Push đúng tag release.
40Registry Logout Xóa credential local. 
docker logout registry.example.com
 Dùng trên máy share/CI runner.
41Compose File config Kiểm tra compose sau khi render env. 
docker compose config
 Luôn chạy trước up production.
42Compose Up stack Tạo/cập nhật stack. 
docker compose up -d
 Dùng -d để chạy nền.
43Compose Down stack Dừng và xóa container/network stack. 
docker compose down
 Không thêm -v nếu không muốn xóa volume.
44Compose Pull image Tải image mới. 
docker compose pull
 Thường chạy trước up -d khi deploy.
45Compose Build service Build service trong compose. 
docker compose build
docker compose build app
 Dùng khi image build local.
46Compose Logs service Đọc log theo service. 
docker compose logs --tail=200 app
docker compose logs -f --tail=100
 Tên service không phải tên container.
47Compose Exec service Vào service đang chạy. 
docker compose exec app sh
 Nếu service scale nhiều replica cần chọn container.
48Compose Run one-off Chạy job tạm như migrate. 
docker compose run --rm app npm run migrate
 Khác exec: tạo container mới.
49Compose Restart service Restart một service. 
docker compose restart app
 Không ảnh hưởng service khác.
50Compose Scale service Tăng replica service. 
docker compose up -d --scale worker=3
 Không scale service publish port cố định giống nhau.
51Compose Profiles Chạy nhóm service tùy profile. 
docker compose --profile debug up -d
 Dùng cho tool phụ như adminer/debug.
52Compose Project name Đặt tên project để tránh lẫn stack. 
docker compose -p myapp up -d
docker compose -p myapp ps
 Project name đổi sẽ tạo network/volume tên khác.
53Compose Env file Chỉ định env file. 
docker compose --env-file .env.prod up -d
 Bảo vệ quyền file env.
54Healthcheck Dockerfile healthcheck Khai báo healthcheck trong Dockerfile. 
HEALTHCHECK --interval=30s --timeout=5s CMD curl -fsS http://localhost:3000/health || exit 1
 Image cần có curl/wget hoặc dùng binary phù hợp.
55Healthcheck Compose healthcheck Healthcheck trong compose. 
healthcheck:
  test: ["CMD", "curl", "-fsS", "http://localhost:3000/health"]
  interval: 30s
  timeout: 5s
  retries: 3
 Sai healthcheck gây cảnh báo giả.
56Troubleshoot Container exited Điều tra container chết. 
docker ps -a
docker logs --tail=200 app
docker inspect app --format "{{json .State}}"
 Đọc log trước khi rm.
57Troubleshoot Cannot connect DB Kiểm tra network/env/port. 
docker compose ps
docker compose exec app printenv | grep -Ei "DB|DATABASE"
docker compose exec app nc -vz db 5432
 Trong compose, host DB thường là tên service.
58Troubleshoot Permission denied volume Debug quyền bind mount. 
ls -ld /host/path
docker compose exec app id
docker compose logs --tail=100 app
 Sửa owner theo UID/GID app chạy.
59Troubleshoot No space left Docker đầy disk. 
docker system df
df -h
docker image ls
docker volume ls
 Dọn image/cache trước; volume phải kiểm tra kỹ.
60Cleanup Prune container/image Dọn container/image không dùng. 
docker container prune
docker image prune -a
docker builder prune
 Không xóa volume bừa.
61Cleanup Prune volume Dọn volume không dùng. 
docker volume prune
 Rất nguy hiểm nếu nhầm volume data.
62Security Non-root user Chạy app không root. 
USER 10001:10001
# hoặc docker run --user 10001:10001 IMAGE
 Cần quyền ghi thư mục phù hợp.
63Security Drop capabilities Giảm Linux capabilities. 
docker run --cap-drop ALL --cap-add NET_BIND_SERVICE IMAGE
 Chỉ add capability thật cần.
64Security Read-only filesystem Giảm khả năng ghi. 
docker run --read-only --tmpfs /tmp IMAGE
 App cần ghi cache/log phải cấu hình.
65Security No privileged Tránh privileged container. 
docker run --privileged IMAGE
 Privileged gần như trao quyền host, tránh production.
66Security Scan image Quét CVE image. 
trivy image --severity HIGH,CRITICAL IMAGE:TAG
 Fix base image/dependency.
67Deploy Release flow Deploy có kiểm tra. 
docker compose config

Delivery room

CI/CD từ kiểm tra code tới deploy production

Module này đi từ Git workflow, test/build, artifact, Docker image, deploy qua SSH/Docker/Kubernetes/Helm, security gate, approval, notification, troubleshooting và rollback. Đây là bảng học chi tiết; phần Tổng hợp lệnh chỉ để copy nhanh.

Master course

Giáo trình master: CI/CD

Học theo 4 lớp: hiểu nguyên lý, làm lab, tự trả lời câu hỏi, rồi xử lý tình huống thực tế.

01

Lý thuyết cốt lõi

Pipeline tốt phải test, build, scan, deploy, verify, rollback và ghi dấu release.

02

Lab master

Tạo GitHub/GitLab pipeline cho app Docker: lint/test, gitleaks, trivy, build image, deploy compose, smoke test.

03

Câu hỏi phải trả lời được

Artifact là gì? Vì sao cần tag bằng commit SHA? Secret scan fail thì xử lý sao?

04

Tình huống thực tế

Deploy xanh nhưng production lỗi do env thiếu; pipeline cần health check sâu và rollback rõ.

 Không deploy khi worktree bẩn nếu chưa hiểu thay đổi.

git diff --stat HEAD~1..HEAD
git diff HEAD~1..HEAD
git show --stat HEAD

04Git Tag release Tag giúp định danh bản phát hành. 
git tag -a v1.0.0 -m "release v1.0.0"
git push origin v1.0.0

05Git Rollback bằng revert Đảo commit lỗi bằng commit mới. 
git revert COMMIT_ID

06Git Hotfix branch Tạo nhánh sửa nhanh từ production/main.

git pull
git checkout -b hotfix/fix-incident

07Pipeline Fail fast Chạy bước rẻ/nhanh trước: format, lint, unit test. 
npm ci
npm run lint
npm test

Defense foundation

Security Mindset / Tư duy phòng thủ

Tư duy bảo mật bắt đầu từ câu hỏi: mình đang bảo vệ tài sản nào, ai có thể nhắm tới nó, đường vào ở đâu, nếu bị xâm nhập thì thiệt hại là gì và lớp phòng thủ nào giúp phát hiện hoặc giảm thiệt hại sớm nhất.

Core thinking

Cách suy nghĩ như người vận hành an toàn

Không có hệ thống an toàn tuyệt đối. Mục tiêu là giảm bề mặt tấn công, giảm quyền khi bị lộ, phát hiện nhanh, cô lập nhanh và phục hồi sạch.

01

Asset first

Liệt kê domain, server, database, bucket, repo, secret, tài khoản admin và dữ liệu quan trọng.

02

Assume breach

Luôn giả định có một lớp có thể bị vượt qua, vì vậy cần defense-in-depth và log đủ để điều tra.

03

Least privilege

Mỗi user, service, token chỉ có quyền tối thiểu, đúng thời gian, đúng phạm vi.

04

Recoverability

Bảo mật không chỉ là chặn tấn công, mà còn là phục hồi nhanh khi sự cố xảy ra.

Phòng thủ Edge/Nginx/WAF

Chặn sớm request độc trước khi vào app: rate limit login/API, giới hạn body upload, deny đường dẫn nhạy cảm, bật security headers và theo dõi spike 4xx/5xx.

  • Deny /.env, /.git, /wp-*, /phpmyadmin nếu không dùng.
  • Đặt client_max_body_size theo nhu cầu thật.
  • Log đầy đủ remote_addr, request_time, upstream_status.

Phòng thủ SSH và quyền máy chủ

SSH là cửa quản trị lớn nhất. Ưu tiên chỉ cho phép qua VPN/Tailscale, dùng key, tắt root/password nếu có thể, và theo dõi mọi thay đổi trong authorized_keys, cron, systemd.

  • Không để quản trị production bằng mật khẩu yếu.
  • Dùng sudo theo nhóm, không chia sẻ tài khoản root.
  • Ghi lại người có quyền và ngày thu hồi quyền.

Phòng thủ dữ liệu và backup

Rủi ro lớn nhất thường không phải web down mà là mất dữ liệu hoặc backup không dùng được. Backup phải tách quyền, có bản immutable/offsite và được diễn tập restore.

  • Tách quyền app, DB, backup và admin.
  • Kiểm checksum backup quan trọng.
  • Định kỳ restore sang môi trường test.

Phòng thủ cloud/container/CI-CD

Đừng để secret nằm trong repo hoặc image. Pipeline chỉ có quyền tối thiểu, image được scan, registry private, cluster có RBAC/NetworkPolicy và không mount socket nguy hiểm.

  • Rotate token khi nghi ngờ lộ.
  • Không dùng cloud key dài hạn nếu có OIDC.
  • Review quyền deploy trước mỗi dự án.

Playbook xử lý sự cố bảo mật

P1 - nghi bị chiếm quyền hoặc lộ dữ liệu: không xóa vội log, ghi lại thời gian, snapshot nếu có thể, cô lập dịch vụ bị ảnh hưởng, khóa đường vào, xoay secret, kiểm tra persistence, restore từ bản sạch và viết RCA. Lab 1: Chặn scanner web

Đọc access log, lọc request vào /.env, /.git, /wp-admin, sau đó thêm deny/rate limit trong Nginx và kiểm tra bằng nginx -t trước khi reload.

Lab 2: SSH chỉ qua mạng riêng

Kiểm tra user đăng nhập, bật firewall chỉ cho phép quản trị qua Tailscale/VPN, kiểm thử phiên SSH mới trước khi đóng phiên cũ.

Lab 3: Secret hygiene
